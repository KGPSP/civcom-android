# CIVCOM Android v1

Publisher: KG PSP. CIVCOM version 1.0.0 (base versionCode1, ABI output codes10–14). Public source: https://github.com/KGPSP/civcom-android.
Upstream Element X Android v26.09.2, commit `477c81399761c02db99f3ae9447a528f3be4d1d7`; upstream history and AGPL/commercial alternative notices remain intact. CIVCOM changes are distributed under AGPL-3.0-only. No Rust SDK fork.

The application preserves direct/group chat, files including audio/video, E2EE verification and recovery. Audio/video calls and maps are disabled at availability, entry, incoming event, manifest and map rendering boundaries. Registration, QR login, password login UI and developer settings are unavailable. The administrator must provision accounts and disable registration on Synapse/MAS; hiding UI is not a server policy.

Official Matrix server `soia.info`, fixed API `https://matrix.soia.info`; the upstream SDK performs OIDC. Authorization URLs require `https://auth.soia.info`. Callback URLs are `pl.gov.psp.civcom:/`, `pl.gov.psp.civcom.debug:/`, `pl.gov.psp.civcom.nightly:/`. OIDC client metadata: `https://civcom.soia.info/apps/android`, original logo `/znak.svg`, owner legal pages `/privacy` and `/terms`. Domain links use `https://civcom.soia.info`. SDK state/PKCE and token storage remain upstream.

Production package and pusher ID: `pl.gov.psp.civcom`. Development: `pl.gov.psp.civcom.debug`; nightly: `pl.gov.psp.civcom.nightly`. These are app-generated constants, not Sygnal guesses. FCMHTTPv1 gateway is `https://push.soia.info/_matrix/push/v1/notify`. The SDK uses `event_id_only`; existing client-secret payload supports notification fetch validation. The OS boundary replaces all notification contents with `CIVCOM — Nowa wiadomość`, without sender, room, body, avatars or reply actions.

No Sentry/PostHog providers are linked in any variant; Rust Sentry logging/configuration and Rageshake upload URL providers are disabled. Inherited workflows are archived under `tools/civcom/upstream-workflows/*.disabled`, preventing publication or upload to Element services. CIVCOM CI has read-only repository permissions and uses no credentials or publishing tasks.

Firebase provisioning uses external original Google-services JSON files: `CIVCOM_FIREBASE_DEV_JSON` for debug/nightly, `CIVCOM_FIREBASE_PROD_JSON` for release. Each must contain the corresponding exact package client; the dev file can contain both development clients. Gradle derives native Android resources, rejects incomplete metadata and the inherited Element project. Missing development config means FCM is inactive; there is no Element fallback. Secrets/service account keys are never committed.

Signed builds require `CIVCOM_RELEASE_STORE_FILE`, `CIVCOM_RELEASE_STORE_PASSWORD`, `CIVCOM_RELEASE_KEY_ALIAS`, `CIVCOM_RELEASE_KEY_PASSWORD`, the appropriate Firebase file, and `CIVCOM_ASSETLINKS_JSON`. The last file is the owner-published Android association for `civcom.soia.info`; the gate checks its package and SHA256 against the actual keystore certificate. Keep credentials external. Validate live domain and OIDC associations before signed device acceptance; a local association fixture is not deployment proof. Release never falls back to the upstream debug/nightly signature.

Local build example: `JAVA_HOME=<external JDK21> ANDROID_HOME=<external SDK37> ANDROID_SDK_ROOT=<same SDK37> GRADLE_USER_HOME=<external cache> ./gradlew :app:assembleGplayDebug --no-daemon --no-configuration-cache`. On the author host, task-scoped IPv4 and TLS1.2 JVM settings repaired official Maven TLS retrieval; certificate verification remained enabled. All source, SDKs, dependencies, temporary data and evidence were stored on MK-BIL.

Author evidence is external under `/Volumes/MK-BIL/PROJEKTY/CIVCOM_ELEMENT/evidence/android`, including argv, cwd, SHA, diff hash, exit and logs. The source report in the coordination workspace lists actual outcomes. Local builds/unit results do not imply independent approval, signed acceptance, production push, E2EE recovery across devices, store clearance or deployment. Publish only after legal distribution review, matching credentials/associations, administrator registration policy and physical-device acceptance.
